# Комната на VDS: ymsync-relay в Docker на Debian

Гайд для случая, когда вы с другом в разных сетях и хотите слушать вместе.
Комнату держит не чей-то ПК, а сервер в интернете. Оба подключаются к нему,
и у вас синхронно играют очередь, позиция, пауза, скипы и «Моя волна».

```
 ваш ПК / телефон ──┐                    ┌── ПК / телефон друга
                    └──► VDS: relay ◄────┘
         звук каждый берёт сам — у Яндекса или со своего диска
```

## Что будет работать, а что нет

| | Через VDS |
|---|---|
| Общая очередь, play/pause, перемотка, скип — командует любой | да |
| «Моя волна» | да: волна того, кто её включил. Если он выйдет, волну подхватит оставшийся |
| Повтор, перемешивание, «играть следующим», список участников | да |
| Старт трека одновременно у всех | да: релей ждёт до 15 с, пока трек загрузится у каждого |
| Раздача треков друг другу (порт 8788) | **нет** |

Раздача работает только в одной локальной сети: за NAT роутера ваш файловый
сервер из интернета не достать. Поэтому релей здесь запускается с ключом
`--no-lan-share` и не рассылает адреса для раздачи, а значит клиенты не ждут
таймаута, прежде чем пойти в Яндекс. Отсюда главное условие:

> **У каждого должен быть свой аккаунт Яндекс Музыки с Плюсом**, и токен должен
> быть вписан в приложение. Каждый скачивает трек со своего аккаунта сам.
> Треки, которые уже лежат на устройстве («Скачанное»), играют с диска.

Сервер нужен самый простой: релей занимает несколько мегабайт памяти и почти
не использует процессор, потому что звук через него не идёт. Берите VDS,
до которой у вас обоих маленький пинг. Если задержка больше 400 мс, клиенты
перестают подстраивать позицию (`max_rtt_ms`).

## Клиенты

Подходят обычные сборки из
[Releases](https://github.com/mshivarev/ym-sync/releases): протокол не менялся,
изменения коснулись только серверной части. Версии у вас должны совпадать,
иначе релей откажет с ошибкой `protocol`. Приложение обновляется само, так что
обычно хватает запустить его у обоих.

### «Моя волна», которая учится

В официальных сборках волна берётся через старый API и Яндексу ничего не
сообщается, поэтому она быстро начинает крутить одно и то же. В этой версии
клиент открывает сессию волны, как это делает приложение Яндекс Музыки, и
сообщает ей, какой трек начался, какой дослушан, а какой пропущен. Пропуск
учитывается, кто бы из участников его ни нажал.

Новая сборка нужна только тому, кто включает волну: подкачивает треки и
отчитывается Яндексу его приложение, с его аккаунта. Остальным подойдёт и
официальная сборка.

Собрать на Windows:

```
cargo build --release -p ymsync-gui -p ymsync
target\release\ymsync-gui.exe
```

Проверить, что Яндекс принимает сессии с вашим токеном:
`target\release\ymsync.exe probe "кино"`. Шаг 6/6 откроет сессию и запросит две
партии треков.

Если кнопка «Доступна X.Y.Z» предложит обновиться, это обновление на
официальную сборку, в которой волна опять перестанет учиться.

## 1. Подготовка сервера

Подойдёт Debian 12 (bookworm) или 13 (trixie). Все команды выполняются от root
или через `sudo`.

```bash
apt-get update
apt-get install -y ca-certificates curl git openssl
```

### Docker из официального репозитория

```bash
install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/debian/gpg -o /etc/apt/keyrings/docker.asc
chmod a+r /etc/apt/keyrings/docker.asc

echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] \
https://download.docker.com/linux/debian $(. /etc/os-release && echo "$VERSION_CODENAME") stable" \
  > /etc/apt/sources.list.d/docker.list

apt-get update
apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

docker run --rm hello-world     # проверка
```

Если `docker pull` падает на скачивании образов с Docker Hub (у некоторых
российских хостеров бывает именно так), подключите зеркало:

```bash
cat > /etc/docker/daemon.json <<'EOF'
{ "registry-mirrors": ["https://mirror.gcr.io"] }
EOF
systemctl restart docker
```

## 2. Код на сервер

Флаг `--no-lan-share` есть только в этой версии репозитория, поэтому на сервер
нужно положить именно её. Подойдёт любой из двух способов.

**Через свой форк** (удобнее обновлять): запушьте эту папку в свой репозиторий,
затем

```bash
git clone https://github.com/<вы>/ym-sync.git /opt/ym-sync
```

**Копированием с ПК** (из папки проекта на Windows, в PowerShell):

```powershell
scp -r Cargo.toml Cargo.lock Dockerfile .dockerignore docker-compose.yml .env.example crates deploy root@IP_СЕРВЕРА:/opt/ym-sync/
```

Папку `/opt/ym-sync` нужно заранее создать на сервере: `mkdir -p /opt/ym-sync`.

## 3. Пароль комнаты

```bash
cd /opt/ym-sync
cp .env.example .env
sed -i "s/^YMSYNC_ROOM_TOKEN=.*/YMSYNC_ROOM_TOKEN=$(openssl rand -hex 16)/" .env
chmod 600 .env
cat .env      # запомните значение YMSYNC_ROOM_TOKEN, оно понадобится в приложении
```

## 4А. Запуск: просто IP и порт (`ws://`)

```bash
docker compose up -d --build
```

Первая сборка занимает несколько минут: компилируется Rust. Проверка:

```bash
docker compose ps          # STATUS: Up … (healthy)
docker compose logs -f relay
```

В логе должна появиться строка `relay listening bind=0.0.0.0:8787 protocol=6 lan_share=false`.

Откройте **TCP 8787** во входящих. Если у хостера есть файрвол в панели,
откройте порт там.

> Docker публикует порты в обход `ufw`: правило `ufw deny 8787` контейнер не
> закроет. Чтобы ограничить доступ, используйте файрвол в панели хостера.

Адрес для приложения: **`ws://IP_СЕРВЕРА:8787`**

## 4Б. Запуск: домен и TLS (`wss://`)

Пароль комнаты при `ws://` уходит открытым текстом. Если есть домен, лучше
закрыть соединение TLS: Caddy сам получит сертификат Let's Encrypt.

1. Направьте A-запись домена (например, `music.example.com`) на IP сервера.
2. Откройте **TCP 80 и 443**. Порт 8787 наружу больше не нужен.
3. Допишите в `.env`:

   ```bash
   YMSYNC_DOMAIN=music.example.com
   RELAY_PUBLISH=127.0.0.1:8787
   ```

4. Запустите:

   ```bash
   docker compose --profile tls up -d --build
   docker compose logs -f caddy     # дождитесь "certificate obtained successfully"
   ```

Адрес для приложения: **`wss://music.example.com`**

## 4В. Запуск: за уже настроенным nginx

Если на сервере уже работает nginx с HTTPS, Caddy не нужен: он не сможет
занять порты 80 и 443. Релей слушает только localhost, а nginx проксирует
к нему WebSocket по пути `/ymsync`.

1. Допишите в `.env`:

   ```bash
   RELAY_PUBLISH=127.0.0.1:8787
   ```

2. Запустите только релей, без `--profile tls`:

   ```bash
   docker compose up -d --build
   ```

3. Вставьте блок из [deploy/nginx-ymsync.conf](../deploy/nginx-ymsync.conf)
   внутрь `server { … }` вашего домена, того, где `listen 443 ssl`.
   Затем проверьте конфиг и перечитайте его:

   ```bash
   nginx -t && systemctl reload nginx
   ```

Адрес для приложения: **`wss://ваш.домен/ymsync`**

Если nginx сам работает в контейнере, `127.0.0.1` из него указывает на сам
контейнер nginx. В этом случае подключите nginx к сети релея
(`docker network connect ym-sync_default <контейнер nginx>`; имя сети покажет
`docker network ls`) и пишите в `proxy_pass` `http://relay:8787`.

## 5. Подключение из приложения

Оба участника делают одно и то же:

1. **Настройки / Комната → Аккаунт Яндекса**: войдите или вставьте свой токен.
2. **Комната**:
   - **название**: любое, например `home`, одинаковое у обоих;
   - **пароль**: значение `YMSYNC_ROOM_TOKEN` из `.env`;
   - **адрес комнаты**: `ws://IP_СЕРВЕРА:8787` или `wss://ваш.домен`.
3. Нажмите **«Подключиться»**, а не «Хостить»: «Хостить» поднимает комнату на
   своём устройстве. Кнопка «Найти в сети» тоже не нужна, она ищет только в
   локальной сети.

В блоке «Кто в комнате» должны появиться вы оба. Теперь кто угодно ставит
трек, плейлист или **«Моя волна»**, и у второго заиграет то же самое с той же
позиции.

На Android поля те же, на экране «Комната».

## Обслуживание

```bash
cd /opt/ym-sync

docker compose logs -f relay                 # логи
docker compose restart relay                 # перезапуск
docker compose down                          # остановить (добавьте --profile tls, если был TLS)

git pull && docker compose up -d --build     # обновить (с TLS: --profile tls)
```

Контейнер с `restart: unless-stopped` сам поднимается после перезагрузки
сервера. Перезапуск релея сбрасывает очередь комнаты: клиенты переподключатся
сами, но очередь придётся поставить заново. Пустая комната хранит очередь
12 часов.

Подробные логи: добавьте `RUST_LOG=ymsync_relay=debug` в `.env` и выполните
`docker compose up -d`.

Сменить пароль: исправьте `YMSYNC_ROOM_TOKEN` в `.env`, выполните
`docker compose up -d` и впишите новый пароль в приложение у обоих.

## Если что-то не так

| Симптом | Причина |
|---|---|
| Приложение не подключается, в логе релея пусто | Порт закрыт: файрвол хостера или для `wss` нет 80/443. Проверьте с ПК: `Test-NetConnection IP -Port 8787` |
| `bad room token` / `unauthorized` | Пароль в приложении не совпадает с `YMSYNC_ROOM_TOKEN` |
| `relay speaks protocol 6, client speaks N` | Разные версии приложения: обновитесь из Releases |
| У одного играет, у другого тишина и «трек недоступен» | У второго аккаунт без Плюса или трек недоступен в его регионе. Через VDS трек у соседа взять нельзя, только в одной LAN |
| Постоянно перематывает, «рассинхрон» | Большой пинг до VDS (> 400 мс) или нестабильная сеть. Возьмите сервер ближе |
| `wss://` не подключается, `ws://` работает | Caddy ещё не получил сертификат (смотрите `docker compose logs caddy`), или A-запись указывает не на этот сервер |

## Без Docker

Тот же релей можно запустить напрямую:

```bash
cargo build --release -p ymsync-relay
YMSYNC_ROOM_TOKEN=секрет ./target/release/ymsync-relay \
  --bind 0.0.0.0:8787 --no-discovery --no-lan-share
```
